# Data Engineering Mini‑Challenge: Superstore Orders & Returns

> **Duration** ≈ 4–6 hours for someone who has never used dbt before.
> **Goal** – Load two Excel files into a local Postgres warehouse with **dbt**, model a simple fact table, and visualise key metrics in a Python notebook.

---

## 1 Project structure (after your implementation)

```text
├── data/                   # raw data files (Excel & converted CSV)
│   ├── Sample - Superstore.xls # you have to download it
│   ├── orders.csv          # you have to create this
│   └── returns.csv         # you have to create this
├── docker-compose.yml      # brings up Postgres, you can change this
├── pyproject.toml          # Python project setup file, add whatever you like
├── scripts/
│   └── xls_to_csv.py       # converts Excel → CSV for dbt, you have to write this!
├── dbt_superstore/         # generated by `dbt init`
|   ├── models
│   |   ├── staging/
│   │   |   ├── stg_orders.sql  # you have to create this
│   │   |   └── stg_returns.sql # you have to create this
│   |   └── marts/
│   |       └── fct_orders.sql  # you have to create this
|   └── dbt_project.yml
└── app.py                  # streamlit app for analysis, you have to write this!
```

## 3 Setup & Common Tasks

Available commands from the justfile:

- Install dependencies:
-  

  ```bash
  just install
  ```
  
- Start Postgres container:  

  ```bash
  just up
  ```

- Run tests (Python tests):  

  ```bash
  just test
  ```

- Run dbt tests for a specific model:  

  ```bash
  just dbt-test model
  ```

- Run any dbt command (e.g., run transformations):  

  ```bash
  just dbt run
  ```

- Run the Streamlit app:  

  ```bash
  just run
  ```

- Stop and remove containers and volumes:  

  ```bash
  just down
  ```

## 4 Get the data

1. **Download** *Sample – Superstore.xls* (public Tableau sample) from the direct link [https://www.tableau.com/sites/default/files/2021-05/Sample%20-%20Superstore.xls](https://www.tableau.com/sites/default/files/2021-05/Sample%20-%20Superstore.xls). This workbook contains three sheets; we will use **Orders** and **Returns** only.
2. Copy it into `data/`.
3. Implement and run the helper script to extract the two sheets "Orders" and "Returns" from the Excel file and store them as CSVs for dbt seeds:

```bash
uv run python scripts/xls_to_csv.py "data/Sample - Superstore.xls"
```

> **Tip:** You can use `pandas.read_excel()` so you can adapt it if you pick a different dataset.

---

## 5 Spin up Postgres

Create the container once and keep it running in the background:

```bash
docker compose up -d db
```

`docker-compose.yml`:

```yaml
version: '3.8'
services:
  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: analytics
      POSTGRES_PASSWORD: analytics
      POSTGRES_DB: superstore
    ports:
      - "5432:5432"
    volumes:
      - ./tmp/pgdata:/var/lib/postgresql/data
```

> Optional: Install a database admin tool such as pgAdmin or use a Visual Studio Code extension (e.g., "SQLTools PostgreSQL/Redshift Driver") to connect to your local Postgres instance.

---

## 6 Initialise dbt

```bash
uv add dbt-core dbt-postgres

dbt init dbt_superstore  # creates dbt_project.yml and models/
```

Create a profile so `dbt` can talk to the local database (`~/.dbt/profiles.yml`):

```yaml
dbt_superstore:
  target: dev
  outputs:
    dev:
      type: postgres
      host: localhost
      user: analytics
      password: analytics
      port: 5432
      dbname: superstore
      schema: analytics
      threads: 4
```

### 6.1 Load the raw tables *(seeds)*

Move the automatically generated `orders.csv` and `returns.csv` into `seeds/` and run:

```bash
dbt seed
```

This materialises two tables under the **raw** schema.

### 6.2 Build transformations

- **stg\_\_orders.sql** – rename columns, cast datatypes, expose surrogate keys.
- **stg\_\_returns.sql** – same pattern.
- **fct\_\_orders.sql** – left join the two staging tables on `order_id` and add a `is_returned` flag.

Execute everything:

```bash
dbt run   # ► builds staging + mart tables

dbt test  # ► generic & custom tests (not null, unique, relationships)
```

## 7 Visualise the KPIs

Create a small web app with `streamlit` and run `streamlit run app.py` to start it. There is also a just command `just run` that will start the app.

Example queries to cover:

```sql
-- total sales & profits
SELECT SUM(sales) AS total_sales,
       SUM(profit) AS total_profit
FROM analytics_marts.fct_orders;

-- return rate
SELECT COUNT(*) FILTER (WHERE is_returned) * 1.0 / COUNT(*) AS pct_returned
FROM analytics_marts.fct_orders;
```

Pair them with:

- **Monthly sales trend** line plot.
- **Top 5 states by revenue** bar chart.

The streamlit app template already contains some boilerplate code to connect to the local Postgres db.
